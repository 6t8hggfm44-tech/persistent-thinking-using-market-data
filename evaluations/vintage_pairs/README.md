# Prospective payroll vintage comparison

Registered November 18, 2026. The unit is one BLS Employment Situation reference month. The first opportunity is **November 2026**, with a scheduled release on **December 4 at 08:30 Eastern**. November 24–27 are its eligible Eastern calendar dates. Start at the first already authorized post-close cycle in that window. This registration reserves events, not forecast IDs or probabilities. Keep existing P000037 and all previous forecasts outside the sample.

## What competes

The November 6 v0.2.21 revision moved four percentage points from H002 (recession) to H001 (soft landing) and H003 (inflation), two each. Its immediate motivator was the missed October payroll magnitude in P000034. v0.2.20 and v0.2.21 share the same causal graph. The two frozen weight records, their commits and the archived benchmark observations are in [design.json](design.json).

On each common evidence packet the Forecaster assesses the conditional probability of payroll growth of at least 100,000 jobs under each of H001 through H004 **once**, with a reason for each. Freeze these four inputs before looking at either weighted result. Use at least two significant digits where justified. Do not round the mixture before scoring. Both arms use the same target, publication, cutoff, evidence and four conditional probabilities. Their difference is exactly 0.02 × (q1 + q3 − 2 × q2). Equal mixtures are valid ties. Do not tune the conditionals for separation. The inputs are judgmental. This controlled comparison isolates the effect of reweighting. It does not reconstruct an independently elicited historical forecaster or test two independently trained systems.

**Benchmark.** Use the single frozen unconditional 30/36 = 5/6 probability for this exact event. The preceding three complete calendar years of BLS initial releases contain 12/12, 11/12 and 7/12 hits. The October 2025 employment change first appeared as −105,000 after a lapse in appropriations. Use that first published value. The benchmark can be poorly matched to a later labor regime, and retains that risk throughout the cohort. The BLS table and archive links and all 36 numbers are in the design. Historical neutral 0.5 references retain their original status.

## Ordinary producer entry point

1. At existing Phase 5, run `python3 tools/payroll_vintage_pair.py status` against the current complete primary snapshot. All 12 consecutive monthly opportunities, November 2026 through October 2027, are in [calendar.json](calendar.json). The UTC times use the BLS calendar published November 9 and Eastern daylight-saving rules. Use the original scheduled date for the 7–10-day lead window even after a delay. If a release is moved forward, never issue after actual publication. Verify the official schedule and unreleased status at issuance. Do not add a run on a holiday or close the cohort early on performance.
2. At the **first existing eligible cycle** that completes the scoring-first, evidence intake, Skeptic and Modeler phases, issue the payroll forecast plus its companion. If a phase gate fails, record why in the cycle and try at the next authorized occurrence in the window. A closed opportunity can only be marked missed. A previously issued or resolved forecast on the same payroll target cannot be retrospectively paired. Preserve duplicates, gate failures and missed opportunities in the coverage denominator.
3. Prepare a private JSON draft using the fields below. Use the next available canonical forecast ID under the normal live-head check. The source commit identifies the primary evidence snapshot after intake. The evidence list contains paths and actual times of complete receipt; verify that the entire referenced evidence is eligible by the cutoff. Keep common information available to both arms. Use precommitted weights even if the live model later changes. For a later live model supply its ordinary probability separately. The script stages that canonical probability independently of both historical arms.

| Draft field | Required value |
| --- | --- |
| `reference_month`, `id`, `live_model_version` | Calendar month, unused P-number, and actual live model version |
| `source_commit`, `evidence_cutoff` | Immutable primary evidence commit and actual post-close UTC cutoff for this cycle |
| `evidence` | Nonempty array of objects with exact primary `path` under evidence/ and UTC `available_at` |

| `live_probability` | Required for a live model outside the frozen versions. For a frozen version the script calculates its probability |

4. Run `python3 tools/payroll_vintage_pair.py prepare PRIVATE_DRAFT.json NEW_PRIVATE_OUTPUT_DIR` from the pinned primary root. It hashes the common evidence and creates both `predictions/open/Pnnnnnn.json` and `evaluations/vintage_pairs/Pnnnnnn.json` with the same creation time. Preserve the checkpoint, then publish **both original files in one commit before release**. Apply the normal branch lease, remote byte verification and duplicate checks against the fresh head. On collision, inspect the new snapshot and retry prospectively only. The program never writes directly into canonical locations or publishes to GitHub.
5. After an unfilled window, run `python3 tools/payroll_vintage_pair.py miss YYYY-MM "actual reason" NEW_PRIVATE_OUTPUT_DIR`. Checkpoint and publish that administrative record at the existing cycle. It cannot earn a score or be backfilled. For each scheduled month, report registered pending, scored, missed, unaccounted or upcoming. Actual first BLS publication governs outcome availability; a postponed or omitted observation stays pending until first published. If the first release is permanently unavailable, retain its explicit unscored disposition.

## Outcome and independent score

Phase 1 resolves only the canonical forecast in the usual ledger. Freeze the original open object unchanged in `original_forecast` plus `resolution.outcome.first_release_nonfarm_payroll_change` as an integer number of jobs, `resolution.outcome.event_ge_100000` as a Boolean, the archived BLS `resolution.source_url`, `resolution.source_published_at` and `resolution.resolved_at`. Compare the actual first publication with the commit that registered both probabilities. A 100,000 change is TRUE. The sidecar remains frozen. Count one observation per release across both roles.

At Friday/month-end review the companion auditor recomputes three Brier and three log losses from that one outcome. Use Brier as the primary decision metric. Show individual losses, the signed current-minus-previous and current-minus-benchmark differences, plus wins, ties, losses, mean loss differences, mean loss margin on losing events and the worst loss margin for each comparison. Positive differences quantify how much worse current was. Show corresponding previous-versus-benchmark performance. Keep the common denominator and all failed/missing windows visible. Zero cases produce no performance estimate. Report earlier and later periods only with counts. Arithmetic ties must stay ties. The 12 planned releases limit this cohort to descriptive evidence under the existing learning thresholds. Preserve all forecasts, including large losses.
